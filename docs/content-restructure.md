## Pages CMSでのnote記事の扱い

「INSIGHTS（お知らせ・ブログ）」から、掲載方法を選択できます。noteは独立したカテゴリーにせず、noteから転載する記事は「ブログ」を選択します。

1. **サイト内に本文を掲載**：タイトル・公開日・カテゴリー・本文を入力。note原稿を手動でコピーできます。「転載元の記事URL」は任意で、設定すると本文下に元記事へのリンクを表示します。画像はメディアに追加し、コピー後の段落と画像を確認します。
2. **noteなど外部の記事へリンク**：タイトル・公開日・カテゴリー・外部の記事URLを入力。本文は不要です。既存デザインの一覧行からnoteへ直接移動します。リンク記事はサイト内に空の本文ページを作りません。

記事原稿の保存先は既存の `site/content/news/` のままです。公開済みURLを変更しないでください。Pages CMSの初回GitHub App導入・管理画面での編集確認は別途必要です。

### Codexに依頼して転載する運用

noteで記事を公開後、「noteの未掲載記事をブログへ反映して」と依頼します。対象の記事URLを添えると、取り込む範囲を明確にできます。Pages CMSへの手動コピーは不要で、Codexが同じ記事原稿ファイルを更新します。取り込んだ後の修正はPages CMSでも可能です。

1. 指定アカウントの記事と既存原稿を照合します。転載元URLがない既存記事も、タイトル・本文で確認して二重掲載を防ぎます。
2. 対象記事の本文・見出し・公開日・リンクを保ち、画像を確認してサイト用の原稿へ取り込みます。取得できない画像や埋め込みがあれば、その箇所を報告します。
3. カテゴリーは「ブログ」、掲載方法は「サイト内に本文を掲載」にし、個別記事のURLを「転載元の記事URL」に記録します。
4. 表示とビルドを確認してGitHub Pagesのデモへ反映します。以後note側の原稿を変更しても、自動同期はされません。修正時も依頼して反映します。

2026-09-07のカテゴリー整理では、新規の記事取り込みは行っていません。

### 自動連携について

自動連携は今回設定していません。通常のnote RSSで取得できるのはタイトル・公開日・画像・本文冒頭などで、サーバー側で取り込む仕組みが必要です。GitHub Pagesでも、GitHub Actionsなどのビルド処理でRSSを取得し、最新記事の一覧とnoteへのリンクを自動更新する構成は可能です。本文まで自サイトへ転載する場合、公式の全文RSSはnote proと独自ドメインの接続が必要です。それ以外の全文取得は本文・画像・埋め込みの抽出と表示確認、仕様変更への対応が必要になるため、当面は依頼ごとの転載を基本にします。

公式資料：[noteのiframeとRSS](https://www.help-note.com/hc/ja/articles/4402395202841)、[全文RSSの条件](https://www.help-note.com/hc/ja/articles/900001001246)。

## CASE STUDYの更新

「CASE STUDY（取り組み・事例）」で、事例名、URL、見出し、紹介文、写真、取り組みの流れ、補足本文を編集します。流れは見出し・取り組み内容・詳細の組で追加や並べ替えができます。保存先は `site/content/cases/` です。

公開フラグをオフにした事例は出力されません。ただしGitHubリポジトリ自体が公開のため、原稿に非公開情報を保存しないでください。製品UIは、写真・動画を含め公開用サンプルに置き換えてから登録します。
